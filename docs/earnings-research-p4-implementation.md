# P4 实施与验收计划

状态：2026-09-16 用户已批准实施。父任务负责 review、master 集成推送和 NAS 上线；独立任务以 gpt-5.6-sol / medium 实施，完成后主动回传，一小时心跳仅兜底。本文与 `earnings-reader-report-design.md` 为本轮批准范围；涉及后续飞书文档的新约定优先于 P0/P3 中“暂不使用飞书 CLI”的旧约束。

## 基线与交付目标

P0–P3 已在 master 实施，NAS 已有每日 10:00 Asia/Shanghai、七天运行、静默的 cc-connect 财报任务。P4 在同一入口上新增季度研究及读者报告，不增加高频任务，不干扰价格行为、账户、交易观察名单和其他工作区。

用户已认可 NVIDIA 样稿，并确认通过 NAS 已配置 lark-cli 生成的飞书文档可正常阅读。正式交付采用本地归档 → 显式用户身份写入用户云空间 → 回读核验 → 本仓库 cc-connect 最终摘要及链接。飞书 CLI 只负责文档，不承担消息发送。运行时凭据、用户/应用路由、文档 ID 和目录 ID 均放忽略配置，不能写入跟踪文件；不改绑 CLI 默认身份或其他工作区机器人。

## 实施内容

### P4.1 读者报告

- 扩展现有财报 Skill、角色说明和输出契约，覆盖公司/IPO、行业季度、跨行业市场报告。内部财务证据和审计报告保持兼容、不可变。
- 增加独立 publication writer 与核对阶段。撰写基于已验收的冻结研究输入及必要原文，不重做整条研究链，不靠模板拼接 claims 冒充自然语言研究。核对数字/单位/期间/链接、关键反证、推断强度及可读性。
- 正文包含一分钟摘要、业务解释、关键变化和数字含义、利润/现金、潜在线索、市场预期未知项、反证、情景、下一次验证点。隐藏原始 JSON、模型/哈希等审计噪声，保留来源定位。
- 对机会明确分析变化、独立证据、利润归属、持续性、市场预期差和验证条件。缺共识或价格数据就标记未知，不虚构超预期、低估或目标价。P5 的预期数据接入不进入本轮。
- 每个已研究公司每季度归档读者报告；关键公司或有依据的重要变化优先交付，其余进入可查目录，避免逐家公司刷屏。同事件新闻稿及 10-Q 归并，后续实质补充形成版本修订。
- Markdown 为正文源，HTML 为本地阅读派生格式；正文、来源映射、版本、前序哈希和核对结果进入 publication manifest。PDF 非本轮必须项。

### P4.2 飞书文档与通知

- 新增标准库 CLI adapter，使用 argv、绝对可执行路径、显式 profile 和 `--as user`，只允许所需文档创建/更新/读取及目标目录查询操作；不打印令牌、不自动改登录/权限、不回退 bot 或另一目标。
- 读取实际 CLI 帮助与安装 Skill。已验证 `docs +create --doc-format markdown` 和 `docs +fetch`；导入需处理引用式链接、本地锚点和相对文件路径。样稿曾由 bot 创建再复制给用户，生产应直接以用户身份创建到核验目录，不能把复制作为每次发布的必经步骤。
- 明确 create/update/readback/delivery 的独立状态、文档 ID/URL/正文哈希、输出语言及版本。失败仅重试当前阶段。已启动写入后返回不明时进入 unknown，不能盲目重试创建或发送。
- 防止写入中间稿：核对通过才同步。正文更新不能误覆盖用户编辑；远端基线不一致时保留冲突或生成有版本标识的新文档，不静默抹掉人工内容。
- 回读检查内容、表格及引用，用户身份可访问才登记全文交付成功。认证失效形成明确失败，不能重新跑研究或自动发起无人可操作的登录。
- 本仓库 cc-connect 是唯一通知发送者。保持 muted，按日合并摘要/目录链接，不因旧逻辑只展示前五项而丢掉其余报告入口。季度正式报告完成即属于可交付事件，即使没有新 alpha、thesis_state 未变；原始 insufficient_data 噪声不能自动刷屏。

### P4.3 季度调度

- 建立固定季度样本、实际经营期间映射和季度依赖状态。区分批次日期、财政期间、自然季度、披露可用截止和报告发布日期。不得继续只按 period_end 所在季度作为正式季度归属。
- 制定可测试、可解释的财政期间映射规则，保留实际起止与重叠差异；不能把年度披露直接当单季。对缺少期间的数据阻止正式季度结论。
- 同一每日入口处理成熟、截止阶段版、修订和人工触发。初次启用应有限度补做最近已结束且材料可用的季度，不把尚未结束季度或全部历史季度一并推入正式研究。
- 成熟门槛沿用至少 90% 核心样本披露覆盖，关键公司齐备、必要公司研究完成及关键证据缺口审查。冻结分母；披露/采集/研究完成分开统计，不因资料缺失就认为公司未披露。
- 真正季度 DAG：覆盖/缺口 → 行业深度研究 → 独立反证 → 综合裁决 → 读者报告/核对。季度角色要复读关键原文和未命中/反对样本，不能仅压缩日更。
- 行业在季尾各自成熟后发布；截止不成熟允许明确阶段版，补齐再修订。失败/超时不能伪装完成。
- 每周日复核缺口、积压和假设待验证事项，随日任务执行。无重要变化保持静默，不强制周周生成长文。

### P4.4 跨行业研究

- 同一季度冻结范围内所有行业完成规定研究验收后，才生成正式市场研究；阶段总览单独标注，不能因截止/失败绕过正式依赖。
- 必须有独立跨行业分析与核对，比较经营变化、改善广度、产业链利润传导、共有客户重复计数、负面证据及可比性；不是拼接行业摘要。
- 当前只覆盖 5 个行业组、30 家公司，标题及正文明确“美股重点行业季度研究”，不得宣称全市场扫描完成。
- 源行业版本变化触发有限修订，保留当时资料截止，不因每日时钟更新而重复启动模型。

### P4.5 可靠性与上线

- 沿用 daily/review/quarterly 的已验证模型分工；新增 writer 使用 daily，核对使用 review，季度深度/跨行业使用 quarterly。读取实际配置，不静默替换模型。
- 保留并发和单任务超时限制；预算覆盖新增角色及实际尝试次数，允许跨日推进，避免新披露或季度任务被长期饿死。初始化与当前事件分配有界；不可把未提供的 token 计量记录成零。
- SQLite 增量迁移兼容 P3 数据，manifest 不可变，锁/租约恢复、幂等/unknown、独立失败隔离均需覆盖。新增 flags 默认关闭，运行配置显式启用。
- 更新 AGENTS/Skill/contract/计划/runbook 中与新交付相冲突的旧文案；保留交易边界。文档说明状态、运维命令、去重/冲突恢复及回滚。

## 重点测试与验收

1. 财年错位、单季/半年/年度、未来季度不提前完结、固定分母及关键公司缺失；90% 达标但关键缺口未解决不得正式发布。
2. 日常研究 → 读者写作 → 核对 → 文档回读 → 通知完整离线测试；伪 CLI/fixture 必须标明离线，绝不能作为生产财报或远端发送成功凭证。
3. 行业季度四阶段及跨行业依赖，通过跨日恢复继续；截止阶段版、补齐正式版及修订不重复。
4. 文本数字/期间漂移、反证被删除、引文不匹配、未知估值变成确定判断、表格/链接丢失能阻断发布。
5. 不同 scope/季度/目标/版本的去重；创建不明/回读失败/消息不明分别恢复；同日多份报告目录完整；远端用户编辑不覆盖。
6. 旧日报及通知逻辑兼容，不改变价格行为任务、真实账户或观察名单。相关模块测试、Python/Shell 语法检查、统一入口回归。
7. 父任务 review 后，在 NAS 独立状态目录先验收：真实公司样稿完整链、至少一个有充分材料行业的季度链，以及多行业依赖门槛。真实样本不足时如实保持阶段版；不能靠fixture打开所有生产门槛或伪称市场季度报告完成。
8. 确认 NAS 仅现有每日 10:00 静默 cron，部署增量配置并回读状态、报告和文档；完成后删除父任务的一小时兜底心跳。
